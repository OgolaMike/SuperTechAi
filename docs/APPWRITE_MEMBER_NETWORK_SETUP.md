# Appwrite member network setup

This setup applies only to the independent Appwrite deployment. It does not change the legacy Supabase/Bolt application.

## Network rules enforced by the Worker

- Company Genesis is the central sponsor and is not itself a team.
- A team is created only by the company-authorized owner provisioning endpoint.
- Every owner is the root of exactly one team. The owner is introduced by Genesis.
- Every ordinary member must activate through an existing active member's opaque referral code.
- The sponsor and team owner are written server-side and cannot be supplied or changed by the browser.
- A member's referral code is generated by the Worker. Appwrite user IDs are never used as referral codes.
- Members cannot create teams, set roles, change uplines, or move between teams.
- A missing upline blocks access to the trading terminal until the company assigns an owner or the member supplies a valid referral code.

## 1. Create the Appwrite table

In Appwrite Console, open database `6b06e4d900325c304d98` and create a TablesDB table with ID `member_network`.

Create these columns (all required unless marked optional):

| Column | Type | Required |
|---|---|---|
| row_type | string (16) | yes |
| user_id | string (36) | yes |
| email | string (320) | yes |
| referral_code | string (36) | yes |
| sponsor_user_id | string (36) | yes |
| team_owner_id | string (36) | yes |
| role | string (16) | yes |
| status | string (16) | yes |
| created_at | datetime | yes |

Create indexes:
- Unique key on `user_id`
- Unique key on `referral_code`
- Key on `team_owner_id`
- Key on `sponsor_user_id`
- Key on `status`

Keep table-level permissions empty. The Worker uses its server API key; do not grant public or member write access to this table.

## 2. Configure Worker variables and secrets

The Wrangler config already sets `MEMBER_NETWORK_TABLE_ID=member_network` and the independent Pages origin. Set the existing Appwrite server key as a Worker secret if it is not already present:

```sh
npx wrangler secret put APPWRITE_API_KEY
```

Set the Appwrite user ID of the company's Genesis account:

```sh
npx wrangler secret put GENESIS_ACCOUNT_ID
```

Set a long, randomly generated company-only authorization token:

```sh
npx wrangler secret put GENESIS_ADMIN_TOKEN
```

Do not put either secret in frontend variables, source code, or a public repository.

## 3. Introduce an owner and create a team

1. The company directly selects and introduces the new owner.
2. The owner creates a normal Appwrite account and verifies their email.
3. The company obtains that account's Appwrite user ID from the trusted Appwrite Console.
4. From a trusted company-controlled terminal, call:

```sh
curl -X POST "https://supertechai-independent-api.mikedavid45.workers.dev/api/company/owners" \
  -H "Content-Type: application/json" \
  -H "X-Genesis-Token: $GENESIS_ADMIN_TOKEN" \
  -d '{"userId":"VERIFIED_OWNER_APPWRITE_USER_ID"}'
```

The endpoint checks the company token, confirms the Appwrite account exists and is email-verified, then creates the owner root row. The response contains the new owner's opaque referral code. The owner signs in and can share their generated referral link from Account.

Never call this endpoint from the browser. Never expose the Genesis token to an owner or ordinary member.

## 4. Member onboarding

A member opens a current member's referral link, creates an account, verifies their email and signs in on the same browser. The app retains the referral code during the sign-up flow and activates the member server-side. If the original browser state is unavailable, the member can paste the inviter's 36-character referral code into the upline verification screen.

## 5. Deploy and verify

After the table and secrets are configured:

```sh
cd workers/independent-api
npx wrangler deploy
```

Then build and deploy the Pages branch using the repository's normal independent deployment pipeline. Verify:
- An unassigned account is stopped at the upline gate.
- A valid member referral code activates the new member.
- The new member's generated link refers the next person to the same owner team.
- A normal member cannot call the company owner endpoint.
- An invalid, expired/nonexistent, self-referral or missing code is rejected.
- The network table cannot be read or written directly by clients.

## Important scope

This implements identity, upline capture, permanent team attribution, company-only team creation and member network counts. It does **not** yet implement TRC20 deposit verification, paid membership transactions, commission calculation, withdrawal execution or a financial ledger. Do not describe referral bonuses as payable until those separate financial controls are built and tested.
